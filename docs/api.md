# FraudShield AI - API Documentation

## 1. API Overview

FraudShield AI exposes REST APIs through a FastAPI backend.

The API handles:

- User authentication
- Dataset uploads
- Transaction analysis
- Fraud predictions
- SHAP explanations
- Investigation workflows
- Fairness metrics
- Dashboard analytics

Base URL:

```
/api/v1
```

---

# 2. Authentication

## Login

Authenticates a user and returns an access token.

### Endpoint

```
POST /auth/login
```

### Request

```json
{
  "email": "analyst@example.com",
  "password": "password123"
}
```

### Response

```json
{
  "access_token": "jwt_token",
  "user": {
    "id": "123",
    "name": "John Doe",
    "role": "Analyst"
  }
}
```

---

# 4. Dataset APIs

## Upload Dataset

Uploads a transaction CSV file for processing.

### Endpoint

```
POST /datasets/upload
```

### Request

```
multipart/form-data

file: transactions.csv
```

### Response

```json
{
  "dataset_id": "abc123",
  "status": "processing"
}
```

---

## Get Dataset Processing Status

Checks background processing progress.

### Endpoint

```
GET /datasets/{dataset_id}/status
```

### Response

```json
{
  "status": "completed",
  "transactions_processed": 250000
}
```

Possible statuses:

```
uploaded
processing
completed
failed
```

---

# 5. Transaction APIs

## Get Transactions

Returns paginated transactions.

### Endpoint

```
GET /transactions
```

Query parameters:

```
?page=1
&limit=20
&status=fraud
```

### Response

```json
{
  "transactions": [
    {
      "id": "123",
      "amount": 5000,
      "type": "TRANSFER",
      "risk_score": 0.92
    }
  ]
}
```

---

## Get Transaction Details

Returns detailed information about a transaction.

### Endpoint

```
GET /transactions/{transaction_id}
```

### Response

```json
{
  "id": "123",
  "amount": 5000,
  "transaction_type": "TRANSFER",
  "prediction": {
    "risk_score": 0.92,
    "result": "fraud"
  }
}
```

# 11. API Processing Flow

## Upload and Analyse Transaction Data

```
1. User uploads CSV
        |
        ↓
2. Dataset record created
        |
        ↓
3. Background job added to queue
        |
        ↓
4. Transactions processed
        |
        ↓
5. Fraud model generates predictions
        |
        ↓
6. SHAP explanations generated
        |
        ↓
7. Dashboard displays results
```

# 12. Error Handling

The API uses standard HTTP responses.

| Status Code | Meaning |
|---|---|
| 200 | Successful request |
| 201 | Resource created |
| 400 | Invalid request |
| 401 | Authentication required |
| 403 | Permission denied |
| 404 | Resource not found |
| 500 | Server error |
